1Dependencies

The debug/release split is the whole safety model — copy it exactly. Debug gets the real SDK, release links the no-op artifact with the identical public API.

Never wrap QaLens calls in if (DEBUG) — the no-op artifact mirrors every public symbol, so release builds compile unchanged and execute nothing.

2L0 — zero code

Nothing to write. AndroidX Startup auto-installs the overlay in debug builds. Build, run, and you already have:

4L2 — screens & navigation

Replace NavHost with QaLensNavHost (same parameters) and every route change lands in the timeline, the screen-visit map, and your recordings.

Not using Navigation Compose? Call QaLens.setScreen("Checkout", route) yourself on screen changes.

5L3 — network & logs

One line each. Both libraries are compileOnly — QaLens never forces OkHttp or Timber on you, and coverage in the .sal says so when a track is absent.

Already running Chucker? Keep its inspector and attach QaLens metadata capture to the same client. Chucker has no public live transaction listener; the old networkFromChucker flag no longer disables QaLens capture.

The sample tests Chucker 4.1.0 with Kotlin 2.0.21. Use a Chucker version compatible with your app's Kotlin/AGP toolchain and matching debug/release no-op artifacts. Full OSS integration contract.

Gate the automatic captures without touching your client code: captureNetwork = false (pass-through interceptor) and captureLogs = false (silent Timber tree). Explicit QaLens.event()/log()/breadcrumb() calls keep working — and analysis.json.coverage records the mode so the .sal never lies about it.

6L4 — enrichment (all optional)

Each line below unlocks one more kind of evidence. Stop at any level.

7Webhook — ship sessions to your analysis backend

One URL in the Control Room. The app POSTs the .sal as multipart with X-QaLens-* headers; the backend's response body appears right under the recording. Try it against the bundled mock backend with zero setup.

Large recordings stream in 1 MB chunks with CRC32 and resume; flaky Wi-Fi gets 3 attempts with backoff plus an offline retry queue — all client-side, contract unchanged.

8Verify

Run these after integrating — the release compile is the check that the no-op parity holds (a missing twin fails the build, never silently at runtime).

Build note: use JDK 17 — Kotlin 2.0.21 cannot parse newer JDKs (gradle.properties already sets kotlin.daemon.jvmargs). Any cached Gradle 9.x binary works if the wrapper download is slow.
